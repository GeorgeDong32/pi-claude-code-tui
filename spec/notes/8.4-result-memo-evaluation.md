# §8.4 result memo 评估结论

日期：2026-10-05（P0–P3 执行期间）。对象：`cc-rows.ts` 的 `newResultMemoSlot` / `renderMemoizedResult`（result 引用 memo，plan A6）。

## 验证方法与证据（pi 1.0.2 `tool-execution.js` 源码 + 行为路径）

| 路径 | host 行为（实测源码） | memo 命中？ |
| --- | --- | --- |
| 普通帧（纯重绘） | `render(width)` 渲染 `updateDisplay()` 缓存的组件树，**不重新调用 renderResult** | 不适用（renderer 不跑） |
| partial（流式） | `updateResult(result, true)` → `updateDisplay()` → 以 `{ content: this.result.content, details: this.result.details }` **构造新 envelope 对象**调用 renderer | **未命中**（`a.result === b.result` 恒 false） |
| invalidate | `invalidate()` → `updateDisplay()` → 同上构造新 envelope | **未命中** |
| 展开 | `setExpanded()` → `updateDisplay()` → 新 envelope（且 expanded 变化本来就该重建） | **未命中** |
| resize | `render(width)` 用新宽度渲染缓存组件 → `ccResult` 内部 `createWidthCache` 重排 | 不经过 memo |

结论：host 每次 `updateDisplay()` 都新建 envelope，引用相等比较在全部真实路径上为 false；普通帧根本不进 renderer。memo 只付出开销（每次调用构造 key、做必然失败的比较、存死状态），没有任何可测收益。

## 决策（按 spec 规则"删除无效 memo"）

- 删除 `ResultMemoSlot` / `newResultMemoSlot` / `renderMemoizedResult`；入口 `resultFactory` 直接调 `ccResult`（与 host 每次 updateDisplay 全量重建 call+result 容器的行为对齐）。
- **保留** `ccResult` 内部的 `createWidthCache`（宽度→布局缓存，resize 语义明确，spec 明示单独保留）。
- 不引入深比较、JSON hash 或全量结果缓存（spec 禁止；亦无需求——重建只在 updateDisplay 边界发生，非每帧）。
